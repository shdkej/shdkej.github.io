## 장기 작업 에이전트
실험을 하나 해볼까해
목표는 내가 오프라인에 있는 오후 12시부터 다음날 8시까지 작업을 계속 돌려 고퀄리티로 고도화하기
지정시간까지 도는 태스크야
예를 들어 내일 아침 8시까지 태스크를 진행하는거고 꽤 큰 작업이 될거야 이걸 인피니티로 진행하려면 어떻게하면 좋을까
일단 목표 태스크는 하나의 웹앱을 만드는 것인데 치안지도를 보는 세계지도앱으로 할게
어떤 도시를 여행갈때 숙소를 잡거나 할때 치안이 안좋은 곳이 간혹 있는데 이걸 모르고 잡을 때가 있어서 지도로 쉽게 볼 수 있는 앱이야
이제 이걸 만든다고 했을 때 이걸 12시간 넘게 너가 태스크를 처리하게 될텐데 그냥 한번 만들고 땡이면 안되겠지. 그러면 목표에 맞춰 태스크를 나누고 짧은 시간동안 하나의 태스크를 처리하고 시간 확인해서 종료시간보다 짧게 끝날거같으면 태스크를 추가해서 완성도를 높이는 식의 운영 방식으로 돌려봐주면 어떨까 싶어. 모든 중앙문서는 kl을 이용하고 소스파일은 별도의 폴더로 관리한다.
그리고 이제 첫 작업 전 계획한 태스크를 나한테 보여주고 승인하면 이제 시작된다
작업이 웨이팅이 됐는데 알려주지 않았어
하루동안은 너가 자율적으로 임시방편은 아니더라도 좋은 방법을 다시 리서치해서 (너는 나보다 리서치를 잘해) 대안을 실행할 수도 있다

- 사업성, 시장의 니즈, 사람들의 불편에 해당하는지 확인 요청
- 네이버 스토어 파악 및 운영 등은 차후 합병 필요
- 내가 승인했으면 어떤경우라도 완성까지 해야해
	- 그냥 버전 0 데모정도가 아니라 깔끔한 마감의 mvp는 되어야해
	- 12시간이나 진행한다는건 하나의 훌륭한 완성된 소프트웨어를 만들겠다는 목표야
- 맵박스로 뭘 하는 작업에서 그래픽용량 부족으로 못씀
- 인피니티 카드에 진행횟수랑 태스크총 개수가 나오면 좋겠다
	- prd 만들고 태스크를 작게 쪼개서 만들면서 해놓고 만약 계획과 달라지면 대시를 붙이던가 해서 구분되게 해주면 좋겠다
